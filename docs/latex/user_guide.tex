\begin{guideintro}
This PDF explains how to \textbf{launch} the DirectX~9 sandbox, what \textbf{hardware} is expected, how \textbf{keyboard and gamepad} inputs map to the vehicle, and how to fix common \textbf{runtime issues}. Build-from-source and CI notes are grouped at the end for developers.
\end{guideintro}

\section{Launch the application}\label{sec:launch}\sectionrule

\subsection{Game build (markers and end users)}
\begin{itemize}
  \item Open the \texttt{Game\_Build} folder from your submission package (or use a folder produced by \texttt{cmake --install} / \texttt{scripts/package\_game\_build.bat}).
  \item \textbf{Double-click} \texttt{maeg4060\_stage2.exe}. Keep the executable in the same directory as the bundled \texttt{Assets} tree.
\end{itemize}

\guidetip{If meshes or textures fail to load, you are almost certainly running the \texttt{.exe} with the wrong working directory. Launch from the folder that contains both \texttt{maeg4060\_stage2.exe} and \texttt{Assets/}, or confirm that relative paths such as \texttt{Assets/models/\ldots} resolve. Optional replacement OBJ/MTL props live under \texttt{Assets/models/replacements/} (see \texttt{README.md} there).}

\section{Hardware and software}\sectionrule

\begin{itemize}
  \item \textbf{Platform:} 64-bit \textbf{Windows} (recommended).
  \item \textbf{Graphics:} \textbf{DirectX~9.0c} rendering path; GPU and drivers should support D3D9. Install the \textbf{DirectX~9 End-User Runtime} (or ensure equivalent system components) if you see missing-D3D errors.
  \item \textbf{Display:} At least \textbf{1280$\times$720}; the window can be resized.
  \item \textbf{Input (optional):} \textbf{XInput-compatible} gamepad (e.g.\ Xbox controller) for analog throttle and steering. Keyboard control works without a pad.
\end{itemize}

\section{Controls}\sectionrule

\subsection{Keyboard}

\begin{center}
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{0.34\linewidth}p{0.52\linewidth}@{}}
  \toprule
  \textbf{Key} & \textbf{Action} \\
  \midrule
  W / S & Forward / reverse (throttle) \\
  A / D & Steer left / right \\
  Space & Brake (or hand brake, depending on build) \\
  Esc & Exit the application \\
  \bottomrule
\end{tabular}
\end{center}

\noindent
Bindings follow the project implementation (\texttt{GetAsyncKeyState}). If your package includes on-screen hints, treat those as authoritative for that build.

\subsection{Gamepad (XInput)}

\begin{center}
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{0.34\linewidth}p{0.52\linewidth}@{}}
  \toprule
  \textbf{Control} & \textbf{Action} \\
  \midrule
  Left stick & Steering \\
  Right trigger & Throttle (accelerate) \\
  Left trigger & Brake / partial reverse \\
  \bottomrule
\end{tabular}
\end{center}

\noindent
Triggers approximate analog throttle; keyboard W/S remain digital.

\subsection{Windmill behaviour (default)}
\noindent
The windmill \textbf{plays automatically by default}. If the shipped windmill asset contains keyframed animation data, the hierarchy animation is advanced each frame; otherwise the blades use a simple code-driven spin for the static mesh path.

\section{Troubleshooting}\sectionrule

\begin{itemize}
  \item \textbf{Missing DLLs / DirectX errors:} Repair or install the DirectX~9 end-user runtime; update the GPU driver.
  \item \textbf{Black screen or device creation failure:} Prefer windowed operation first, close other exclusive full-screen apps, then retry after a driver update.
  \item \textbf{Assets not found:} Run from the folder layout in Section~\ref{sec:launch}; verify \texttt{Assets/} sits beside the executable.
  \item \textbf{Gamepad ignored:} Prefer a wired connection or official wireless adapter; confirm Windows lists the device as XInput.
\end{itemize}

\section{Build from source (developers)}\sectionrule

The CMake target \texttt{maeg4060\_stage2} expects legacy \textbf{D3DX} headers and import libraries (\texttt{d3dx9.h}, \texttt{d3dx9math.h}, \ldots), which the Windows 10/11 SDK alone does not provide. Configuration uses either:
\begin{itemize}
  \item \textbf{June 2010 DirectX SDK:} set \texttt{DXSDK\_DIR} to an installation whose \texttt{Include/} and \texttt{Lib/} trees CMake can consume; \emph{or}
  \item \textbf{NuGet D3DX:} leave \texttt{DXSDK\_DIR} unset and allow CMake to fetch \texttt{Microsoft.DXSDK.D3DX} on first configure (requires network; first configure may take several minutes).
\end{itemize}

\noindent\textbf{Suggested command line} (matches \path{scripts/configure_build_release.bat}):\par
\smallskip\noindent
Run \path{vcvars64.bat} from your Visual Studio install, then from the repository root:
\begin{verbatim}
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release ^
  -DCMAKE_CXX_COMPILER=cl -DCMAKE_C_COMPILER=cl
cmake --build build
\end{verbatim}
\noindent
Ninja with an explicit \texttt{-DCMAKE\_CXX\_COMPILER=cl} avoids some generator detection issues seen with the Visual Studio CMake workflow. If you switch generators, delete the \path{build} directory (or wipe \texttt{CMakeCache.txt} and \texttt{CMakeFiles/}) before reconfiguring.

If the compiler reports \textbf{C1060} (compiler out of heap space), rebuild with less parallelism, e.g.\ \texttt{cmake --build build -j 1}.

\smallskip\noindent
\textbf{Alternative (Visual Studio generator):}
\begin{verbatim}
cmake -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
\end{verbatim}
\noindent
Use this when the toolset is detected correctly.

\smallskip\noindent
\textbf{Package output:} run \path{scripts/package_game_build.bat}, or \texttt{cmake --install build --prefix Game\_Build}, to populate \path{Game_Build/}.

\section{GitHub Actions (optional)}\sectionrule

If enabled on your fork, \texttt{.github/workflows/windows-build.yml} builds on \texttt{windows-latest} and publishes a zip containing \texttt{maeg4060\_stage2.exe}, \texttt{D3DX9\_43.dll} when the NuGet D3DX path is used, and a copy of \texttt{Assets/}. Unzip on Windows and run the executable from that folder with \texttt{Assets} alongside it.
